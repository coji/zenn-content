## これはなに？

ひとりで開発しているOSSの保守3件を、追加のLLM費用なしで回した記録です。対象はGitHubのPR滞留時間を測る開発生産性ダッシュボード[coji/upflow](https://github.com/coji/upflow)で、依存更新、Draft表示の機能追加、ログイン不能の修正まで含みます。図と写真入りの記録ページも作っています。別タブで開いて眺められるものです。

https://bt9furluuc.artifactshare.link

作業はターミナルで動くコーディングエージェントOpenCodeに任せ、モデルはMetaが提供する推論モデル`muse-spark-1.3-contributor-free`の無料枠を使いました。無料枠は入力と出力を学習に提供する代わりに割引になるcontributor tierという料金体系で、回数制限と地域限定があります。contributor tierは毎分60リクエストなどの上限があります。条件は公式の料金表で確認しています。今回の分量では制限に当たらず、請求は追加なしでした。

https://developer.meta.com/ai/models/muse-spark

この記事の初稿も同じ組み合わせで書いています。人間は方針の決定と最終確認だけしています。

## 依存更新は低リスク順に流して見送りを残しました

#445ではNodeとpnpmの更新、CIの後継アクションへの移行、minorとpatchの更新を先に固めました。
メジャー更新14件は破壊的変更を1件ずつ調べ、低リスク順に当てています。小さなものから着手し、画面に触る大きな移行は後回しにしています。

見送り3件は理由を残して据え置きました。better-authは1.6.5に、parquetjsは1.8.7に据え置きました。型エラーと読み込み不可のためです。octokit系は対応待ちのためです。壊れた2件は無理に含めず外しています。

コミットは作業単位で分け、後から追える形にしました。検証はフルスイートの実行に加えて、影響の出そうな12画面を実機で開いて確かめています。

```sh
# 人間が出した指示はこの程度です。以降はエージェントが調査と適用を回しました
pnpm / nodejs を最新にしたい。あわせて pnpm v12 の github actions を最新にするのもためしてみたいな
```

## Draft除外とログイン400は原因特定が核です

#450は朝会で使う画面の要望が起点です。人間の指示は「review stacks の画面で draft 状態を見分けられるようにしたい」の一文でした。Review Stacksに混ざるDraftを除外と識別で見分けられるようにしました。取得はできているのに保存していないことがわかったので、列を追加して永続化し、既存分も補っています。表示は除外フィルターと識別表示を付けました。テストは634件が通っています。

#451は本番のログイン不能の修正です。人間の報告は「シークレットウィンドウでログインボタンを押したら Bad Request になる」の一文でした。ブラウザからの送信だけがBad Requestになり、curlでは再現しませんでした。ブラウザで再現して切り分けたところ、同一オリジン判定が原因でした。プロキシ越しの組み立てが原因で、修正は1行と確認テストだけです。悪意ある送信は弾いたままにし、デプロイ後に本番で直ったことを確認しました。

## 無料枠を使うときの線引きは学習利用です

使った無料枠は入力と出力を学習に提供する代わりに大幅割引になる料金体系です。見せたコードは学習に使われる前提です。そのため公開済みの自分のOSSだけを対象にしました。鍵や顧客データや非公開仕様は流さない線引きにしています。エージェント側はコードを保存しませんが、モデル提供者にはデータが届きます。この2層を分けて考えています。

無料枠には回数制限と地域限定があり、将来変わり得ます。終わった場合の受け皿は標準料金になります。標準料金の単価も公開されていて、Cursor公式のCursorBenchでは低コスト帯に出ています。使う前に公式の最新情報を確認しておくと安心です。

## 学習に困らないOSSなら無料枠で回せますという話でした

依存更新のような後回しにしがちな作業ほど、**方針だけ決めてエージェントに流す**相性がよかったです。見送りの理由を残すことと、実機で開いて確かめることだけ人間が守れば、保守は回りました。業務で使うなら、会社許可なしの社内コードは流さず、公開情報の整形など学習に困らない範囲に限定できますという話でした。

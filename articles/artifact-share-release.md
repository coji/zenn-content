## 「最新版どれですか」が戻ってきた

Claude Code に調査レポートや比較表を頼むと、きれいな HTML を吐いてくれますよね。それを Slack に添付して送る。修正が入る。また添付する。数日後、チャンネルには `comparison_final_v2.html` と `comparison_final_v2_fixed.html` が並んでいて、誰かが聞くわけです。

「最新版どれですか?」

この問題、実は一度解決済みでした。エンジニアは git で、非エンジニアは Google Docs で解決していたはずなのに、AI が HTML ファイルを吐く働き方とともに戻ってきた。進歩すると、戻るものもあるんですね。

## みんな一回、自作する

で、エンジニアはどうするか。「S3 に置いて URL を配る君」を自作します。作りますよね。ぼくも作りました。

でも、この手の間に合わせは定着しません。アクセス制御がないので社外に見せられないし、URL が毎回変わるので「最新版どれですか」も消えない。そして何より、アップロードが人間の手作業のまま残ります。AI が作ったものを、人間が手で運んでいる。ここが面倒の正体でした。

## 会社を横断できる置き場所がなかった

ぼくは業務委託で複数社の案件を掛け持ちしています。プログラマーとして入っている会社もあれば、アドバイザーとして入っている会社もあって、どの会社でも仕様やアーキテクチャ案、調査レポート、提言を AI で HTML 化してクライアントに共有したい。

ところが、この立場に合う道具がありませんでした。各社の社内ツールは会社ごとに違い、ぼくのアカウントがない会社もある。Claude の Team プランには成果物の共有機能がありますが、業務委託のぼくはどの会社の Team にも属していないし、一社でだけ使えても困る。必要だったのは、どの会社の契約にもぶら下がらない、会社横断で使える置き場所でした。

ないので、作りました。それが Artifact Share です。

https://artifactshare.com/ja

## ほぼ無料で回すための Cloudflare Workers / D1 / R2

設計方針は最初から決まっていました。価値のほとんどは AI 側にあって、共有サービス自体に大きな価値はない。だからタダ同然で回せる構成にする。そこで選んだのが Cloudflare Workers + D1 + R2 です。Workers はリクエスト課金で待機コストがほぼゼロ、D1 の無料枠はメタデータには十分広く、R2 は egress 無料なので共有 URL がどれだけ踏まれても転送料の心配がありません。

実測はこうです。直近 24 時間で Worker リクエスト約 11 万、D1 クエリ約 47 万、R2 のストレージは 518MB。これで請求は Workers Paid の $5/月に、従量課金が今月ここまでで 1 セント (R2 のストレージ分) です。

## D1 で本当に大丈夫なのか

DB を D1 に決めるまでは結構迷いました。マルチテナントの SaaS で、もしユーザーが急に増えたらどうするのか。Turso や Supabase も検討して、最後は AI に相談したら「D1 でいい。レプリケーションもあるし、テナントが 1 社突出したら、そのときにそこだけ別の D1 に分ければいい」と返ってきて、それで決めました。

とはいえ怖かったので、実測が取れたいま試算し直してみました。実測の比率 (1 リクエストあたり D1 クエリ 4.2、クエリあたり行読み取り 7.1、リクエストあたり行書き込み 1.1) をそのまま DAU 10 万人に伸ばすと、こうなります。

- リクエスト月 2,500 万 → Workers Paid の込み 1,000 万を超えた分が **月 $4 ほど**
- D1 行読み取り 月 7.4 億 → 込み枠 250 億の **3%**。$0
- D1 行書き込み 月 2,650 万 → 込み枠 5,000 万の内側。$0
- ピークでも D1 クエリは 800/秒 ほど。読み取りはリードレプリケーションで逃がせる

つまり DAU 10 万でもインフラは月 $20 前後で、課金が跳ねる要素がありません。実制約は 1 データベース 10GB の上限だけで、これは相談したときの答えのとおり「大きいテナントだけ別の D1 に分ける」で逃げられる。それ以上の規模になったら、そのとき考えます。

そして数字より効いているのが速さです。Worker の CPU 時間は P50 で 6.6ms。D1 は Worker と同じ場所で動くのでクエリが数 ms で返ってきて、外部の DB サービスに海を越えて往復しない構成は体感がまるで違います。

もちろん無傷だったわけではなく、ほぼ AI 任せで作っていた最初期には、マイグレーションの事故で DB を 2 回ふっとばしています。ただ、この手の事故は起きるたびに検証のハーネスを作ることで簡単に潰せて、以後は起きていません。DB と ORM の選定やこのあたりの失敗談は、9/9 (水) の[イベント](https://offers-jp.connpass.com/event/402907/)で詳しく話す予定です。

ここからは、自作で足りなかった 3 つを順に潰していきます。

## デフォルトでは社外に出ない

まず共有範囲。投稿した直後のファイルは社外に出ません。会社のワークスペースなら社内全員まで、個人なら自分だけ。社外の人に見せるときだけ、期限付きの共有リンクを発行します。「リンクを知っていれば誰でも見える」を既定にしない、というだけの話ですが、クライアント向けの文書はこれがないと始まりません。

## URL は変わらない。中身が最新になる

次に「最新版どれですか」。同じ URL で次の版へ更新できるので、修正しても URL は変わりません。相手に送ったリンクはそのままで、開けば最新になっている。Google Docs が当たり前にしていたことを、AI 生成 HTML でも当たり前に戻しただけです。

これが絵に描いた餅でない証拠として、公開時点の実数を挙げます (ぼく自身のワークスペースは除いた数字です)。ファイル 559 件に対して版は 1,734。57% のファイルが少なくとも一度は同じ URL のまま更新されていて、平均 3.1 版、最多のファイルは 44 版まで重なっています。作って終わりではなく、直して見せ直す使い方が実際に主流です。

## コメントが Claude Code に還ってくる

最後の 1 つが本体です。共有した HTML には閲覧者がコメントを付けられます。そのコメントを Claude Code が CLI (`as`) 経由で回収し、修正して、同じ URL で次の版へ更新して、返信まで書きます。

CLI の要点は「人間が叩く」ことではなく「Claude Code が使う」ことです。正直、この CLI がなければこのサービスは使いものにならないとすら思っています。人間がやるのは、Claude Code に「as でシェアして」「コメント見て直して」と言うだけ。レポートを作らせたら、そのまま「シェアして」と続ける。翌朝「コメント来てたら対応して」と言えば、修正版が同じ URL に上がって、コメントには返信が付いています。MCP サーバーもあるので、CLI を意識せずに使うこともできます。

実物のデモを一つどうぞ。

https://artifactshare.com/a/lqs8hfvt02

Artifact Share の製品説明スライドですが、これ自体が Claude Code に作らせて「as でシェアして」で上げた HTML です。URL は永続なので、この記事の公開後に直しても、このリンクのまま最新になります。

## 実際に回っているユースケース

使われ方を 3 つだけ挙げます (社名が出ない範囲で)。

1 つ目は**操作できる UI モックの仕様詰め**。画像と違って動く HTML なので、コメントが「この操作のとき」と具体的になります。ある管理画面のモックは、6 版とコメント 62 件の往復で仕様が固まりました。

2 つ目は**ロードマップや KPI ガイドを同じ URL で育てる**使い方。ある事業計画は 23 版まで重なっていて、会議のたびに最新版がそこにあります。

3 つ目は**データ分析・現状報告レポート**。読み手の質問がコメントで付き、次の版で答える。ある計測レポートは 7 版とコメント 25 件の往復になりました。

タイトルの集計でも仕様・設計が最多で、分析ダッシュボード、調査、メモ、スライドと続きます。冒頭に書いた「クライアント向け文書」の働き方が、そのまま数字に出ています。

個人的に一番気に入っている使い方も紹介させてください。kenn さんの Mac アプリ Kanary で、クライアントとのオンライン MTG を録音しておきます。

https://kanary.download/voice

MTG が終わったら、Claude Code に「Kanary で文字起こしして、議事録にして、as でクライアントにシェアして」と言う。これだけで議事録が相手に届きます。しかも過去の議事録も as にあるので、Claude Code が出席者の名前や前回までの文脈をそこから拾えて、使えば使うほど議事録の手直しが減っていく。この「積み上がるほど楽になる」感じは、ファイルを Slack に流していた頃にはなかったものです。

## 全社導入の話が来て、料金を作った

ある会社から「全社で使いたい」と言われました。うれしい話ですが、無料のままだとストレージコストでぼくが赤字になります。

コスト構造を見ると、かかっているのはほぼストレージだけ。なのでシート課金はやめました。高いし、人数を数えるのがダルい。全員に配ってこそ意味のある道具なのに、人数で値段が変わると導入の稟議も面倒になります。料金は 100GB まで月 4,500 円、ユーザー数は無制限。ストレージだけ見ていればいい料金なら、導入する側と運営するぼくの両方で計算が楽です。

ちなみにこの記事を書いている時点で、課金してくれている会社が 2 社あります。うち 1 社はアメリカのスタートアップのようで、どうやって見つけてくれたのかわかりません。個人の Plus プランにも 1 人。特に宣伝はしていないので、静かにお金を払ってくれる人がいるのは不思議な気分です。

## ソースコードは公開、セルフホストもできる

ソースコードは GitHub で公開しています。

https://github.com/artifactshare/artifactshare

ライセンスは Artifact Share Source-Available License という自前のもので、日本語版が正本です。自組織でのセルフホストは自由で、競合する SaaS としての提供だけを制限しています。社内に置きたい会社は自分で動かせますし、ぼくに何かあってもデータは手元に残せます。

とはいえ、デプロイにはいろいろ設定があって手間がかかります。まずは無料版を個人アカウントで使って、雰囲気を見てもらうのがいいと思います。クレジットカードの登録は不要で、無料でも 100MB まで使えます。HTML は普通 30〜50KB とかになるので、それなりに使えるはずです。
